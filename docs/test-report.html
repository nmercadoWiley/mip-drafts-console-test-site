Editor Reminder Merge Test Report

Results of testing Daniel's Editor Delay Tracker (EDT), Gayatri's MIP Drafts Console, and the merged MIP Drafts Console v2 against the same real export. The aim was to confirm that v2 keeps everything the two original tools do.

Tested 29 Sep 2026Chrome on Windows · browser agent + testerData: MIP Summary Report, PRP Lead Ayaka Adachi
Verdict

v2 passed. No regressions, and every EDT feature is accounted for

  • No regressions. With its new settings turned off, v2 produced the same numbers as the original MIP console on every measure checked.
  • EDT's behaviour was verified end to end. 41 of 43 tests passed. The one failure was an error in the expected result, but it also revealed a labelling quirk that v2 had copied. That quirk is now fixed.
  • v2's new behaviour matched predictions exactly on all three configurations tested.
  • Testing found 5 issues. All are fixed in v2.1. The fixes were checked in a test harness but still need a quick browser re-test.

At first the agent couldn't read local file:// pages. This was solved by enabling "Allow access to file URLs" for the extension. It was a tooling problem, not a defect in either product.

Stage 0 · before the browser tests

Where the two tools disagree

The same export was run through both tools' rules. EDT flagged 9 papers for editor action and MIP flagged 25. They agreed on 8, and those 8 went to the same recipient.

  • 17 papers were flagged only by MIP. In 15 of them, the cause is EDT's Health Check rule: a paper marked "On Track" is never delayed in EDT, even when it has 2 or more reviews waiting for a decision or no reviewers invited at all.
  • 1 paper was flagged only by EDT (3771449). It has 14 reviewers invited, 1 accepted, and that reviewer is overdue. EDT sends it to the editor. MIP sent it to the EA. v2 now sends it to the editor, as EDT does.
  • Recipients matched on all 67 papers MIP routed, so moving to MIP's recipient rules carries little risk.

The full paper-by-paper list is in the Editor Reminder Rule Map, under "What happens on the same export".

Limits

Not covered, and next steps

  • Not tested:
    • CSV upload in either tool (EDT-07, V2-18).
    • The Activity Tracker path in v2, meaning uploading it alongside the Summary Report.
    • Portfolios other than Ayaka Adachi's. HEPR had almost no editor-stage papers, so almost all of the evidence comes from JDE.
  • Browser re-test of v2.1: Run 3B, steps V2-12 to V2-16, plus the new Copy plain text button.
  • Decisions still open (see the Rule Map): whether Health Check is used in the delay rule, the email template and subject line, and whether EA notes should appear in editor emails.
  • Sign-off: Daniel should confirm that v2.1 covers his workflow before EDT is retired. The companion guide shows how he'd use v2.1.
  • Second portfolio: before rolling out to the team, run one more portfolio, ideally one with more editor-stage papers than HEPR.
