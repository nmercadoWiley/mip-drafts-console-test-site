# Maintainer guide

**For:** whoever changes the code, templates or rules · **Version:** console v2.2 · **Last updated:** 1 Oct 2026

The console is one HTML file with no build step, no server and no framework. It reads uploaded Excel or CSV exports, works everything out in the browser, and writes drafts and workbooks. Two people built it with AI assistance (Gayatri: the MIP Drafts Console; Daniel: the Editor Delay Tracker features), and AICOE merged it. This guide covers what you need to change it safely.

## 1. Repository layout

| Path | What it is | Who edits it |
|---|---|---|
| `mip-drafts-console.html` | **The tool.** Everything is in this one file: styles, page, templates block, script. | Maintainer |
| `templates/templates.json` | Approved email wording. **This is the source of truth.** The console carries a copy. | Template owner, through the admin page |
| `admin/template-admin.html` | Template editor. It has its own copy of the template engine. | Maintainer |
| `tests/` | Regression kit: synthetic fixtures, runner, baselines, anonymiser | Maintainer |
| `docs/` | Rules, data model, guides, test records | Maintainer / BA |
| `archive/` | The two original tools. **Read-only reference.** Don't edit. | — |

## 2. Inside `mip-drafts-console.html`

The file is in four parts, in this order:

1. **`<style>`.** All the CSS.
2. **The page.** Five tab panels, `tabPanel1` to `tabPanel5`. Each step is a `<div class="card">` with an id, such as `summaryCard`, `delayCard` or `editorCard`. Default settings are the `value` and `checked` attributes on the Step 03 inputs.
3. **The `mipTemplates` JSON block**, between the `BEGIN/END MIP TEMPLATES` comments. It's generated by the admin page. **Don't edit it by hand.**
4. **The main `<script>`.** It's split into sections with banner comments. Search for these headings:

| Banner | What's there | Key functions |
|---|---|---|
| `STATE` | The global variables for Tab 1 | `RAW_ROWS` (upload as parsed), `ROWS` (normalised rows), `COLMAP` (column → header), `ANNOTATIONS` (what happened to each row), `FILTERED_ROWS` |
| `FILE HANDLING` | Reading files and mapping columns | `smartSheetToJson` (header detection, skips "Applied filters"), `loadRows`, `COLUMN_ALIASES` (**the column names the tool expects**), `NO_DECISION_CHECK_STAGES` |
| `FILTER BAR (Step 02)` | Journal, health and editor filters | `computeFilteredRows` |
| `CATEGORIZATION` | **Routing rules** | `isAuthorRow`, `EA_SIDE_PERFORMERS`, `effectiveAccepted`, `categorizeByReviewerProgress` (**the core rule**), `triageBucketKey`, `BUCKET_LABEL`, `EA_NOTE_TEXT` |
| `v2.2 TEMPLATE ENGINE` | Wording | `loadTemplates`, `T(template, field)`, `tplHtml` (wording → safe email HTML), `tplText` (subjects), `applySectionLabels` |
| `MAIN GENERATION` | The **Generate all drafts** button | `generateAll` (calls the routing rules, applies the Step 03 settings, fills `ANNOTATIONS`, renders every Tab 1 output), `routeRowToDict`, `setNotDraftedReason`, `markAnnotation` |
| `EMAIL BODY` | Editor and triage emails | `richTable` (the 13-column table), `resolveSignOff`, `buildPersonEmail` |
| `RENDER: …` | The draft cards, EA summaries, stalled queue | `renderPersonDrafts`, `renderEaDrafts`, `renderInactivitySummary`, `computeProxyLastEditorActionDate` (**the estimate used when there's no Activity Tracker**) |
| `PRPL SECTION` / `STEP 8` | Steps 10 and 11 | `renderPrplSection`, `renderLongPendingSection`, `LONG_PENDING_STAGE_GROUPS` |
| `ACTIONS` | Copy, .eml, exports | `copyHtml`, `buildEmlString`, `downloadEmlZip`, `buildPerJournalWorkbooksZip`, `downloadAnnotatedData`, `ROW_HIGHLIGHT_RULES` |
| `MINIMAL HAND-WRITTEN XLSX BUILDER` | Writes .xlsx files directly, with real colours, % formats and filters | `buildWorkbookBytes(sheetSpecs)`, `buildZipStored`. The sheet spec takes `headers`, `rows` or `sections`, `isDateCol`, `highlightRules`, `percentCols` and `autoFilter`. |
| `TAB 2 — REVIEWER REMINDERS` | Reviewer reminders | `RR_PERF_ALIASES`, `rrLoadPerf`, `rrPassesStatusAndDecisionFilter`, `rrGenerateAll`, `rrBuildReminderEmail`, `rrComputePendingGroups` |
| `TAB 3 — EA OVERDUES` / `TAB 4 — AUTHOR TASKS` | Stage overdues | `EA_STAGES_DEFAULT`, `AUTHOR_STAGES_DEFAULT`, `STAGE_DEFINITIONS_OFFICIAL`, `renderEaOverdueResults`, `renderAuthorOverdueResults` |
| `TAB 5 — EDITOR PERFORMANCE` | Editor KPIs and charts | `epLoadFile`, `epBuildGroupStats` (**all KPI definitions**), `epRenderCharts`, `epRenderDecisionBreakdown` |
| `RSS & SPECIALIZED REVIEWERS` | Tab 2, Step 07 | `SRA_ALIASES`, `sraComputeSpecializedGroups`, `sraRenderRss` |
| `v2 — MERGED FROM EDITOR DELAY TRACKER` | Step 05b and the Chief Editor workbook | `buildDelayGroups`, `delayPct`, `ceInclusion`, `ceExport`, `tpDiffersFromHe`, `RIQ_VIDEO_URL` |

**Order matters at load time.** The templates block must come before the main script. `applySectionLabels()` runs straight after `BUCKET_LABEL` is defined, because `V2_ACTION_LABELS` (Step 05b) and the export categories read the labels later. Don't move `loadTemplates()` below those.

## 3. Common changes

| I need to… | Do this | Then |
|---|---|---|
| **Change email wording** | Use `admin/template-admin.html`. **Don't edit the code.** See the README. | Run the tests and accept the expected wording diffs with `--update` |
| **Handle a renamed Power BI column** | Add the new header name to the right list in `COLUMN_ALIASES`, or `RR_PERF_ALIASES`, `SRA_ALIASES`, `ACTIVITY_COLUMN_ALIASES`. Keep the old name too. | Run the tests. Update `docs/data-model.md`. |
| **Change a default setting** (grace days, stale invites, 30-day stalled queue, 365 days) | Edit the `value` attribute of the input in Step 03, 05 or 11 of the page | Update the help text next to it, `docs/business-rules.md` and the Confluence decision log |
| **Change a routing rule** | `categorizeByReviewerProgress` (editor sections), `triageBucketKey` (triage), `isAuthorRow` / `EA_SIDE_PERFORMERS` (exclusions), or the v2 blocks in `generateAll` (all-overdue, Health Check). **Only once the rule is approved on the decision log.** | Add a fixture scenario in `tests/make_fixtures.py` that shows the new rule, run `--update`, and describe the change in CHANGELOG |
| **Add a field to a template** | Add the field to `templates/templates.json`, to `META` in the admin page (label, required, placeholders), and to the builder that renders it (`buildPersonEmail`, `renderEaDrafts` or `rrBuildReminderEmail`) | Rebuild the console's templates block with the admin page's **Update console file** |
| **Add a new placeholder** | Add it to the `vars` object in the builder, and to the template's `placeholders` list in `META`. Add a sample value to `SAMPLE` in the admin page. | Run the tests |
| **Change a stage list or the stage definitions** | `EA_STAGES_DEFAULT`, `AUTHOR_STAGES_DEFAULT`, `STAGE_DEFINITIONS_OFFICIAL`, `LONG_PENDING_STAGE_GROUPS`, `NO_DECISION_CHECK_STAGES` | Update `docs/business-rules.md` |
| **Add an export column** | Map it in the export function (`downloadAnnotatedData`, `ceExport`, …). For a percentage, pass `percentCols`. For a filter, pass `autoFilter: true`. | Open the file in Excel to check it |

**The template engine is copied in two places:** the console and the admin page. If you change `tplHtml` or `tplText`, change both, or the admin preview will drift from what's actually sent.

## 4. Safety rules built into the code

- **Escaping.** Every value from a report (titles, names) is escaped before it goes into HTML. Template formatting is applied *before* placeholders are filled, so a title containing `**`, `<script>` or `</script>` can never become markup. Keep this order if you change `tplHtml`.
- **No storage.** The console doesn't use localStorage, cookies or network calls, apart from loading the SheetJS library from cdnjs. Keep it that way (decision AU-3). The **admin page** does keep an unsaved draft in its own localStorage. That's deliberate: it holds no manuscript data.
- **Fail visibly.**
  - Missing reviewer columns show the yellow "Heads up" warning.
  - A missing templates block logs an error and leaves the wording blank, so it's obvious.
  - Unknown `{{placeholders}}` stay visible in the draft rather than disappearing.

## 5. Release checklist

1. The rule change is approved on the Confluence decision log, or the wording is approved by the template owner.
2. The code or templates are changed, following section 3.
3. `node tests/run.js` passes. If the change was intended, run `node tests/run.js --update` and check that the diff is exactly what you meant.
4. If routing logic changed, test once in Chrome or Edge with a real export. Mask it first with `python tests/anonymise.py`.
5. `CHANGELOG.md` has an entry. If a rule or default changed, also update `docs/business-rules.md` and the Confluence decision log.
6. Bump the version shown in `<title>`, the `<h1>` and the footer.
7. Commit in GitHub Desktop, using `vX.Y: what changed` as the summary.
8. Tell users where the new file is. Until the tool is hosted, people keep whatever copy they downloaded. The footer shows the template version, so you can check.

## 6. Known technical debt

| Item | Risk | Note |
|---|---|---|
| SheetJS loads from a public CDN | Breaks offline or behind strict networks, and is a supply-chain risk | Bundle it before hosting (readiness checklist #7) |
| ~~3 embedded Power BI screenshots with real data~~ | — | **Fixed** 15 Oct 2026: replaced with text instructions |
| Editors identified by name text | Splits or merges editors | Needs an editor ID in the report |
| A single ~970 KB, 7,100-line file (about 5,500 lines of script) | Hard to review | If it's hosted, consider splitting it into modules, with the test kit as a safety net |
| Tab 2 variable names say "activity" (`RR_ACTIVITY_ROWS`) but hold the MIP Summary Report | Confusing | Historical naming. Rename carefully, with tests. |
| Thresholds in Tabs 3 and 4 aren't saved, and default to 1 day | Users have to re-enter them every session | Waiting on PRP to set benchmark values (business rules #9) |
