What this means

Things to resolve before scoping the hosted solution

Two measures of "overdue"

The action tools ask whether the editor actually needs to act. The dashboard and Aria use Health Check, which Daniel and Iris called misleading on 29 Sep. Unless PRP picks one, an EA's reminder list and a manager's dashboard will disagree.

AI and data governance

Portfolio Insights sends manuscript and editor details to an AI model, which only works inside Claude.ai. In a hosted Wiley site, this needs an approved AI service or has to be removed.

Aria's data is frozen

Aria's KPIs (May 2025–Apr 2026) and staff names ship inside the file. They age, and they need rebuilding to update. A hosted version needs a data feed, which overlaps with Wiley Tech's Research Exchange data layer.

Duplicated features

Editor emails exist in three styles. Editor performance exists in three places. Pipeline-by-stage views exist in three tools. Pick one home for each.

Proposal to confirm with Iris

A finish line in layers

  1. Release 1, Action: host MIP Drafts Console v2.2 (MIP + EDT) with Wiley sign-in, for PRPLs and one pilot vendor. Sign off the open rules and retire the old copies.
  2. Release 2, Oversight: add Portfolio Insights' unique features to the same site as a PRPL view: trends, bottleneck recommendations and KPI benchmarking. That depends on deciding the overdue measure and removing or replacing the AI calls.
  3. Separate track, Analytics: keep Aria / PeerPulse as the managers' analytics product, aligned with the Research Publishing data-layer work. The hosted tool links to it rather than absorbing it.
